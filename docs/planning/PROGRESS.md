## 产品边界冻结

`v0.5.0` 继续严格遵守以下边界：

- 不把产品扩成通用聊天助手
- 不引入自动跨会话长期记忆
- 不引入多 Agent 编排
- 不引入真实外部搜索、真实登录或新的后端平台能力
- 不把 follow-up draft 从“本地可恢复缓存”改成正式历史版本
- 不把左侧历史从 formal versions 视图改成自动注入记忆入口
- 不把产品顺手扩成复杂工作台、长期记忆系统或通用对话平台

如某个改动会影响以下任一语义，必须先暂停确认：

- 历史逻辑
- 归档逻辑
- 删除逻辑
- draft 逻辑
- follow-up 交互语义

本轮已确认的品牌与公开边界：

1. README 开始从“内部开发记录”逐步转向“公开 GitHub demo 首页”
2. 对仓库中可隐藏或可下沉内容先做审计，不直接删文件
3. 真实 LLM API 与飞书链路如需接入，必须保持纯环境变量方式，不写入任何密钥、真实凭据或私有链接
4. 允许调整前端展示名和品牌文案，但如触及包名、模块名、导入路径、仓库名、接口契约或归档标题规则，必须先确认

## 执行顺序

为避免 `v0.5.0` 滑向“顺手重做产品”，执行顺序固定如下：

1. `M1`：先修版本状态、规划文档与工程说明的一致性
2. `M2`：再做 README / 运行说明 / fake-real 模式 / 公开 demo 叙事收口
3. `M3`：然后审计可隐藏的开发辅助文件、状态文档与工程残留，先列清单不预删
4. `M4`：最后做必要验证、小范围展示文案调整与推送收口

每一步都必须满足以下约束：

- 不新增后端主能力
- 不改既有 API 契约语义
- 不重做分层结构
- 不引入与当前目标无关的大规模重构
- 每轮修改都同步补文档、类型与测试覆盖
