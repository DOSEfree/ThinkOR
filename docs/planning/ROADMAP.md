# ThinkOR 公开路线图

> 面向用户与贡献者的公开路线图。内部实施细节与每个小版本的开发步骤不在此公开。
> 路线会随验证结果持续演进，变更记录见 [CHANGELOG.md](CHANGELOG.md)。

## 我们想做的事

一句话：让想法拥有自己的生命周期——从一句模糊的念头，一步步演进成一份可执行、可归档、可继续完善的方案。

大多数聊天机器人把"想法"当成聊天记录里的一段文字：上下文一长就受影响，一次聊天结束想法就沉没了。
ThinkOR 把想法当作一个**对象**：它有状态、有版本、有证据、能归档，任何一次追问都服务于同一条想法线，而不是重新开始。

## 进行中（当前版本 v0.8.0）

目标：修复"默认追问 + 默认商业化"两类偏置，让澄清行为可验证，让版本演进可见。

- 有界澄清判定协议：默认直接分析，只在缺失信息致命时追问，并透明展示判定理由
- 商业化偏置修复：输入可声明想法意图，个人自用不再被默认当成商业产品分析
- 澄清回归测试集：让每一次提示词改动都可验证、可对比，防止行为退化
- 版本对比：左右同屏对比当前版与上一版，修改处高亮，历史保留只读入口

## 规划中（方向，可能调整）

> 以下为长期探索方向，会随验证结果调整，不构成交付承诺。

- 证据源扩展：用户自供链接证据箱、GitHub 自动检索（软件 / 技术类想法）、通用网页搜索、知乎 / 小红书
- 编排架构升级：以 LangGraph 显式建模想法生命周期（状态、检查点、人工确认）
- 多智能体协作：评审循环与专家组讨论，让方案更全面、更多角度

## 原则

- 想法不是聊天记录，而是一个可演进、可版本化、可归档的对象
- 宁可诚实地说"未检索验证"，也不编造一个看似完整的答案
- 路线会变，因为想法会演进——这正是 ThinkOR 在做的事
