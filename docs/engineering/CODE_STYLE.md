# 代码风格

## 总体原则

代码风格以“清晰、稳定、低认知负担”为第一原则。

我们优先写出：

- 容易读懂的代码
- 容易测试的代码
- 容易让 Agent 可靠修改的代码

------

## Python 规范

- 使用 Python `3.12+` 语法风格
- 所有新增代码默认添加类型注解
- 单个函数尽量只做一件事
- 避免超长函数和超大文件
- 明确区分输入模型、领域对象与基础设施代码

------

## 命名规范

- 文件名使用 `snake_case`
- 变量与函数使用 `snake_case`
- 类名使用 `PascalCase`
- 常量使用 `UPPER_SNAKE_CASE`

------

## 结构规范

- 路由层不直接堆业务逻辑
- Prompt 模板不内联在复杂业务函数里
- 外部服务调用统一收口到基础设施层
- 数据结构优先使用 `Pydantic` 模型

------

## 工具规范

- 使用 `ruff format` 负责格式化
- 使用 `ruff check` 负责 lint
- 使用 `mypy` 负责类型检查
- 使用 `pytest` 负责测试

------

## 测试规范

- 每个新增核心模型至少配套一个测试
- 每个新增核心流程至少配套一个最小可运行测试
- 测试名称应清楚描述行为，而不是只描述函数名

------

## 文档规范

- 管理与协作文档默认使用中文
- 面向外部生态的名称、库名、API 名保留英文
- 功能变更若影响行为，应同步更新相关文档

------

## 禁止事项

- 不要无理由一次性大规模重构
- 不要把实验性逻辑直接混入主流程
- 不要为了“显得高级”引入超出当前阶段的复杂框架
