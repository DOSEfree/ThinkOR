# 产品定义

## 项目名称

IdeaOS-Agent

------

## 产品定位

IdeaOS-Agent 不是通用 AI 助手。

IdeaOS-Agent 是一个面向想法孵化阶段的 Idea Development System。

系统聚焦于把原始、模糊、尚未成形的想法，转换成可理解、可讨论、可执行的计划。

------

## 用户输入

用户提交一个想法。

示例：

“我想做一个 AI 宠物翻译器。”

“我想做一个给儿童使用的学习应用。”

“我想开发一个智慧农业系统。”

------

## 核心交互模型

IdeaOS-Agent 的差异化【押在交互模型上】，而不是「输出更长更专业」。

一个通用大模型拿到一句模糊想法，会倾向于把空白处全部脑补填满，给出一份自信但大量臆测的报告。IdeaOS 反其道而行：它要帮用户【看清想法还差什么】，而不是【替用户把想法写完整】。

因此核心交互是：

想法 →（信息充分则直接分析；信息不足则先返回一轮关键问题）→ 用户补充 → 结构化分析。

两条具体要求：

- **假设透明化**：凡是用户没说、由系统补足的前提，必须显式标注为「假设」，不得当作事实陈述。
- **单轮澄清**：信息不足时，系统先抛出最关键的 2–3 个问题，由用户补充后再生成分析。

硬边界（区别于聊天机器人 / 长期记忆）：

- **单轮、有界**：最多问一次、补一次、出结果。不做多轮自由对话。
- **无自动跨会话记忆**：澄清上下文在单次交互内完成，系统默认不将历史记录自动注入后续分析链路。当前 `v0.2` 已支持显式保存历史记录用于归档与回看，但这不等于默认长期记忆。

补充说明：

- 当前 `v0.3.0` 已支持基于当前完成结果或任意已完成历史节点继续 follow-up，并在确认后生成新版完整方案
- 当前 `v0.3.0` 已支持“历史记录列表 / 线程导航 / 历史详情查看 / 从任意已完成节点继续”的显式交互
- 即使进入 `v0.3.0`，历史记录也仍保持为用户显式调用，而不是后台自动记忆

------

## 预期输出

系统应生成以下内容：

1. 想法摘要
2. 可行性分析
3. 市场分析
4. 知识缺口分析
5. 资源缺口分析
6. 团队需求分析
7. 相似项目参考
8. MVP 路线图
9. 长期发展路线图

在 `v0.2` 中，完成态分析还会补充以下归档结果：

- `session_id`：串联同一会话中的原始输入、澄清与最终分析
- `archive_status`：表示当前会话是否已触发、完成或失败于归档
- `archive_url`：归档成功后返回的飞书文档链接

------

## 非目标

当前 `v0.3.0` 仍不构建以下能力：

- 通用聊天机器人
- 个人助理
- 自动跨会话长期记忆系统
- 自主执行 Agent
- 多 Agent 框架
- 社交平台
- 推荐系统

这些方向未来可以评估，但不属于当前 `v0.3.0` 主线范围。

------

## 产品哲学

每一个想法都是一粒 Idea Seed。

系统存在的意义，是帮助这粒种子更快、更清晰地成长。

系统始终聚焦于想法本身，而不是围绕用户做人格化陪伴。

------

## 工程哲学

优先简单架构。

优先可维护性。

优先可解释性。

避免过度设计。

避免过早优化。

当前目标是验证价值，而不是追求形式上的完美。

------

## 成功指标

用户是否能在一次主要交互中，把一个模糊想法转化为清晰的可执行路线？

如果可以，系统就达到了阶段目标。
